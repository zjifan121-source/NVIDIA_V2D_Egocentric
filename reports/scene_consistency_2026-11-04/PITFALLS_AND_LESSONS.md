# Scored20 场景一致性冲刺：坑与经验（2026-11-04）

重建线在冻结前最后 24 小时的全部教训。按模块归类，每条写清症状、怎么发现、为什么之前没看见、怎么修、修没修好。不含人名；"手修线""策略线"指队内另外两条工作线。

## 0. 一句话结论

重建指标（无 GT 代理、官方 AUC）对一整类缺陷免疫，这类缺陷只在场景装配后、策略训练时才暴露，每发现一个就要烧掉一轮 2–4.5 小时的训练。冲刺里连续撞上三个这样的坑（假握、对称物体伪自旋导致手公转、细物体伪滚转），加上质心偏移与桌面高度，是"物体更准却训不出来"的原因。基线从 0.752 到 0.765 的增量全部来自把队友已打分的单段提交逐行合并进基线；我们自己训的段到写稿时还没有 Kaggle 分数。

## 3. 指标盲区

- **无 GT 代理（mask IoU + 深度残差）**：看不见绕对称轴/长轴的旋转、厘米级深度平移、网格尺寸错与位姿错的区别、穿桌与手物穿插；可被每帧重配准"追 mask"博弈。只能当门槛和大错误探测器（校准：差 ≥0.1 可靠，0.01–0.1 多半对，<0.01 噪声）。
- **贴后接触指标（机器人手离物体面 ≤1 cm 帧占比）**：对假握、公转、滚转全部为 1.0。正确的不变量：握持段内手在物体坐标系里的方位角恒定，attach 造成的手腕位移中位 ≤2 cm（杯子），细物体按转角步长 p95 <10°、最大 <25° 和放手一致性。
- **own-ref 与 Kaggle**：own-ref × 重建因子不能预测单段真分（两个 own-ref 更高的手修换入在 Kaggle 上分别 −0.006 和 −0.131）；每个候选都必须探针。
- **尺寸审计高估 CD-O 收益**：CD-O 是 Sim(3)，尺寸被去掉；且 Kaggle 用提交网格配准物体坐标系，换网格会连带位姿板。换网格的合法路径只有"重跟踪 + 重训"。

## 4. 流程与协作经验

- **只追加、不覆盖、每次一个变量**：每个版本一个前缀，父提交钉死，逐文件 SHA 回读；版本名要带内容（objects/hands/support 分别写明），"过渡版"最容易被拿错。
- **一段一个 bundle**：手要写进 bundle，不要放子目录。
- **谁改物体谁重跑手阶段**；手阶段每个场景过"方位角/位移"不变量，不只看贴后距离。
- **坐实后再查质心、再查深度桌面与倾斜**：三项都是一行脚本的事，却各值一轮训练。
- **探针与合并**：单段换入严格可加（五次验证，误差 ≤0.00002）；队友已打分的提交文件可用客户端下载后逐行合并，不需要 run 目录；候选按六板 rank-sum 裁定，不按 AUC；基线每次更新都六板同交。
- **名次分布不均**：AUC 进一名要 +0.07，SP-SR/MP-SR 一段成功就是一名，CD-O 差 0.00005；优先级要按名次成本排。
- **GPU 排程**：吞吐按并行数均分，多并行不加速；每段 100M 在 A6000 约 2 小时、A100 四并行约 4.5 小时；起跑截止要留给评测与打包；大回放配方（38 GB）要按显存排。
- **多会话协调的失误**：消息排队未读时两个会话各自把同一段的原版训练停掉，导致优先段一度没有任何有效训练；冻结段（基线已 0.92+）被排进队列浪费 4 GPU 小时；教训是队列文件只有一个写者、每条指令要回执。
- **分工**：按段分工，不向其他线索要材料；缺的东西从公开数据（HF、已打分的提交）自己推。

## 5. 验证有效的做法

1. 同实物别段的自家 mesh 重跟踪（ep33 勺代理 +0.20，ep28 锅 +0.0145）。
2. 原始手 → loader 清洗 → 贴到最终物体（ep5 在队友处 own-ref 0.25 → 0.887）。
3. 桌面坐实（frame-0 穿透 0）。
4. 质心移到壳质心（倒角 25° → 4.8°）。
5. 杯子自旋由手决定（杯 own-ref 0.32 → 0.57，单种子）。
6. 逐行合并已打分的单段提交（0.752 → 0.765）。
